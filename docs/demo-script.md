# GroundDesk 三分钟中文演示脚本

## 演示前准备

- 使用无痕窗口打开公开落地页；
- 另开一个已登录管理员控制台标签页；
- 确认 Demo Workspace 已初始化、知识文档为 `ready`、最新评测已完成；
- 不预先生成聊天答案，现场问题走真实 API；
- Demo 订单：`GD-2026D019` / `demo.customer19@example.com`。

## 0:00–0:25｜五秒价值与可信边界

话术：

> GroundDesk 是一个双语可信 AI 客服 SaaS。它不是“上传 PDF 后聊天”：每个事实回答必须带可展开的真实来源；资料不足时会拒答并创建人工工单；订单和退货通过白名单工具处理，模型不能执行 SQL、退款或修改订单。

操作：展示 Hero 右侧流程动画，指出绿色代表有证据回答，暖橙代表资料不足并转人工。快速滚动到评测区，说明数字来自数据库最新真实运行，不是页面常量。

## 0:25–1:05｜真实 RAG 与引用

操作：进入 `/demo`，点击：

> LinkCore C240 线材的保修期是多久？

话术：

> 这里的“理解问题、检索知识、校验证据、生成回答”由服务端 SSE 事件驱动，不是前端定时器。问题会先用 BGE-M3 生成查询向量，再和 PostgreSQL 全文检索做 RRF 融合。模型只看到通过阈值的证据。

回答结束后展开引用：

> 引用卡片展示真实文档名、章节或页码与原文片段。服务端还会检查回答中的引用编号是否属于本次证据；校验不通过就修复一次，仍失败则拒答。

## 1:05–1:35｜订单 Tool Call

点击：

> 查询订单 GD-2026D019，下单邮箱是 demo.customer19@example.com。

话术：

> Agent 只能选择 allowlist 中的订单工具。服务端用 Zod 重新校验订单号和邮箱，再执行固定的参数化查询。两项必须匹配；返回的姓名、邮箱和物流单号会脱敏，模型拿不到任意数据库查询能力。

指出界面中的 Tool 状态和结构化摘要，不展示原始 JSON。

## 1:35–2:05｜低置信度拒答与人工接管

点击“新建会话”，再点击：

> 你们是否为火星殖民地提供维修服务？

话术：

> 这个问题故意不在知识库中。系统不会让模型凭常识补答案，而是说明现有资料不足、保留已检查来源，并创建人工工单。提示注入、政策冲突、连续工具失败和用户明确要真人也走同一可靠接管边界。

## 2:05–2:35｜控制台闭环

切换到管理员控制台：

1. Overview：指出会话、引用覆盖率、接管率、延迟和成本都由日志实时计算；
2. Knowledge：打开一份 `ready` 文档并预览 Chunk、章节和更新时间；
3. Tickets：打开刚创建的工单，指出 AI 摘要、接管原因、引用和工具轨迹；
4. Evaluations：展示 26 条真实运行结果与失败案例入口。

话术：

> 管理员能管理知识、商品、订单、成员和设置；客服只能看到分配给自己的工单，关键设置和商品写入会在导航、API 权限和 SQL 查询三层受限。

## 2:35–3:00｜工程与收尾

打开架构区或 README 架构图：

> 前端是 Vue 3 + TypeScript，API 是 Fastify；Supabase 提供 Auth、PostgreSQL、Storage 和 pgvector；DeepSeek 负责生成与工具选择，SiliconFlow 提供多语言 Embedding。所有业务访问都经过 Node API，Workspace 同时有服务端授权和 RLS。自动化覆盖单元、集成、Playwright E2E 与真实 Provider Smoke Test。

结尾：

> 这个项目最核心的工程选择，是把模型限制在“语言理解和解释”上，把证据、权限、订单和退货规则留在可验证的系统边界里。

## 追问备用演示

- 退货确定性：`订单 GD-2026D019，demo.customer19@example.com，Orbit H5 已拆封，不想要了，能退吗？`
- 邮箱不匹配：把订单邮箱改成 `wrong@example.com`，确认不泄漏订单内容。
- 中英文：切换 English 后重新提问，确认界面、空状态和回答语言一致。
- 角色权限：使用 `agent@demo.grounddesk.app` 登录，证明 Settings/Products 不可写且跨 Workspace 返回 403。
