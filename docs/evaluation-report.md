## 用例构成

评测集由 `supabase/seed/002_evaluation_cases.sql` 可重复写入：

- 8 条商品或政策知识问答；
- 5 条订单查询；
- 5 条退货资格；
- 4 条知识库无答案问题；
- 2 条文档提示注入或越权攻击；
- 2 条跨 Workspace 数据隔离检查。

每条用例使用确定性期望值，包括引用文档、工具名称、拒答/接管、退货状态和隔离结果。Mock Provider 只用于验证评测执行器和 CI 回归，不作为公开模型质量成绩。

## 真实改进记录

本轮实现没有隐藏失败。下表来自开发过程记录；Demo Reset 会清理旧评测运行，因此数据库只保证保留重置后重新执行的最新结果：

| 阶段      |    结果 | 暴露的问题                                                                     | 修复                                                                                |
| --------- | ------: | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 初始 Live | 21 / 26 | 规划 JSON 偶发被代码围栏包裹；有效航空政策相似度略低；退货问题被路由成订单查询 | 宽容提取 JSON 后再做 Zod 校验；用真实相似度分布校准阈值；对完整退货凭据约束工具选择 |
| 第二轮    | 22 / 26 | 普通知识问题仍依赖模型规划，产生格式波动                                       | 普通知识/未知问题直接进入受控检索；只有工具意图使用模型规划                         |
| 第三轮    | 25 / 26 | 弱品牌关键词命中让量子计算问题绕过证据阈值                                     | 混合检索的关键词旁路同时要求最低向量相似度                                          |
| 第四轮    | 25 / 26 | 模型把商品描述写入 `productSku`                                                | 只接受用户原文中明确的 `AVL-...` SKU；否则单商品订单传 `null`                       |
| 第五轮    | 25 / 26 | 一条正确检索的中文答案引用格式不完整                                           | 同一证据上执行一次温度为 0 的引用格式修复；仍失败才拒答                             |
| 最新 Live | 26 / 26 | 无失败                                                                         | 保留该结果作为当前公开基线                                                          |

这种修复顺序遵守可信边界：不会为了提高通过率而降低引用校验、允许模型自由回答或把预期结果复制成实际结果。

## 运行方式

```bash
pnpm eval:smoke
pnpm eval:live
pnpm eval:report
```

`eval:smoke` 使用可控 Provider；`eval:live` 会真实调用外部模型并产生少量费用。评测会话标记为 `evaluation`，不占公开 Demo 日额度，也不进入运营看板或人工工单队列。

## 已知边界

- 当前 Retrieval@5 的 8 条知识样本与 Demo 商家资料一致，不能外推为所有行业的通用准确率。
- 成本日志采用可配置的 DeepSeek 峰值、缓存未命中费率做保守估算；供应商实际缓存和峰谷计价可能更低。
- 未使用 LLM Judge 作为唯一真值。后续可以把它作为辅助观察项，但确定性断言必须保留。
- 公开部署后仍需从部署环境再次运行真实 Smoke Test，验证网络、密钥和数据库连接没有环境差异。
