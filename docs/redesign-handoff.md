# GroundDesk 求职展示改版交接

## 预览与范围

- 分支：`codex/grounddesk-showcase-redesign`
- 基线：`main@b7f0c83`
- 本地预览：先运行 `pnpm build`，再运行 `pnpm preview:web`，访问 `http://127.0.0.1:4173`
- 本轮只改首页、公开 Demo、直接相关展示组件、前端状态与测试；没有修改 API、数据库、认证、路由地址、AI/RAG/Agent、环境变量或部署配置。
- 没有合并到 `main`，没有推送或部署，没有增加付费。

## 改动摘要

### 页面重排

- 首页改为“深色价值首屏 + 浅色高可读工作台”，首屏直接说明有依据回答与人工接管。
- 首页静态预览明确标注为非实时示例，使用知识库中已有的 Flux 100 事实，不伪装模型调用。
- 三个场景分别解释有资料可答、资料不足和人工处理；评测与安全边界下移。
- `/demo` 改为聊天优先的约 2:1 双栏；商品资料折叠为上下文，不再挡住提问入口。
- 三个推荐场景只填入输入框，不自动发送；技术轨迹默认收起；桌面引用位于右侧，手机引用位于消息内。
- 商品、评测分别加载和报错；商品失败不再阻塞聊天或让首页丢失其他成功数据。

### 前端逻辑修复

- 修复商品与评测被单个 `Promise.all` 绑定的问题，两个公开读取现在有独立加载、错误和重试状态。
- 修复流式事件修改原始消息对象、导致引用面板计算状态不更新的问题；事件现在更新 Pinia 数组中的响应式消息。
- 修复订单演示邮箱在 Vue I18n 中未转义 `@`、导致资料面板渲染失败的问题。

## 三分钟演示脚本

### 0:00–0:35：首页价值

“GroundDesk 解决的不是模型能不能聊天，而是客服回答能不能核查。首屏展示三条边界：事实回答带引用，订单与退货走受控工具，资料不足时创建人工工单。右侧明确是界面示例，不冒充实时模型结果。”

### 0:35–1:00：三种结果

“向下看，同一个入口会产生三种清楚结果：资料命中时给答案和原文；证据不足时停止猜测；需要真人时把会话、来源、原因和工具记录带进工单。”

### 1:00–1:45：公开 Demo 与引用

“进入 Demo 后，聊天和输入框先出现，商品只作为折叠上下文。点击‘查产品与保修’只会把问题填入输入框，我确认后才发送。回答完成后，右侧显示引用标题；展开后可以核对章节和原文。技术轨迹默认收起，不打扰普通用户。”

### 1:45–2:20：失败与人工接管

“再新建会话，选择‘资料不足怎么办’。如果检索没有可靠依据，系统应明确说明资料不足并创建人工工单，而不是自由回答。当前线上公开数据端点处于 500 状态时，我会如实展示错误和重试状态，不把它说成模型已验证。”

### 2:20–2:40：受控订单工具

“右侧给出明确标注的模拟订单。按钮仍然只填入订单号和邮箱，服务端匹配后才返回脱敏状态；模型不能执行任意数据库查询。”

### 2:40–3:00：工程边界

“首页下方展示真实评测记录和安全边界。页面不再宣传口径有疑问的 Retrieval@5。浏览器没有服务端密钥，退货资格由确定性规则判断，Workspace 同时由服务端校验与 RLS 隔离。”

## 项目所有者需要亲自理解的五点

1. 为什么公开回答必须先有证据，检索为空时不能让模型自由回答。
2. 引用对象如何从 SSE 事件进入 Pinia，再分别展示到桌面资料面板和移动端消息内。
3. 订单查询与退货判断为什么是白名单工具/确定性规则，而不是任意 SQL 或 LLM 猜测。
4. 商品、评测、聊天为什么必须分别呈现状态；健康端点只说明进程和配置存在，不等于每条业务查询可用。
5. 自动化截图为何使用确定性测试 Provider，以及它与真实 Provider Smoke Test、线上验收的证据边界。

## 未验证项与已有依赖

- 未验证：真实 DeepSeek/Embedding 问答、真实线上引用与人工工单、真实登录后台浏览器回归、公开改版 URL；本轮没有部署。
- 既有依赖：Supabase、DeepSeek、SiliconFlow、Render Free。没有新增账号、资源或套餐。
- Render Free 会休眠；本轮观测到健康端点唤醒约 20 秒。投递前是否升级由项目所有者另行决定。
- DeepSeek 与 SiliconFlow 余额/额度未核对，因此没有主动进行付费 Smoke Test。

## 撤回方法

- 当前改动只存在于独立分支。切回原版本：`git switch main`。
- 需要继续验收时切回：`git switch codex/grounddesk-showcase-redesign`。
- 不要在含未提交修改时删除分支；本轮不执行合并、删除分支或部署。
