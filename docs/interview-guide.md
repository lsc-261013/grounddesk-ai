# GroundDesk 面试问答

## 1. 这个项目为什么不是“上传 PDF 后聊天”的套壳？

**回答：** GroundDesk 的核心不是聊天 UI，而是可验证的业务闭环。文档要经过格式校验、Hash 去重、结构化解析、版本化 Embedding 和混合检索；知识回答必须通过证据阈值、冲突和引用完整性门禁。订单查询需要订单号与邮箱双凭据，退货资格由确定性规则工具计算。无答案、提示注入或工具失败会创建带上下文的人工工单。控制台还能管理数据、查看真实用量与运行评测。

**深入追问：** 模型被限制为语言理解、白名单工具选择和结果解释。身份、权限、SQL、政策结论和不可逆操作都不交给 LLM。

## 2. 为什么使用混合检索，而不是只用向量？

**回答：** 客服资料既有语义问题，也有 SKU、型号、政策名等精确词。向量检索擅长语义，全文检索擅长精确字符串。数据库函数分别取得两路排名，再用 RRF：`1/(60+vector_rank) + 1/(60+keyword_rank)` 合并，避免直接比较两种不可同尺度的原始分数。

**深入追问：** RRF 只用于排序。拒答阈值仍作用于 BGE-M3 余弦相似度，并对关键词旁路要求最低向量相关性，避免“有一个弱品牌词就回答完全无关问题”。

## 3. 如何防止更换 Embedding 模型后新旧向量混用？

**回答：** `embedding_configs` 保存 provider、model、dimensions 和独立 `index_version`。每个 Chunk 关联一个配置，检索必须传当前激活配置 ID。数据库列固定为 `vector(1024)`，环境校验也要求 1024 维；模型或维度变化需要创建新配置并重建索引，而不是覆盖旧向量。

**深入追问：** 这同时解决可回滚与审计问题：可以知道某次引用使用了哪个 Embedding 版本，重建失败也不会污染当前可用索引。

## 4. 引用是模型生成一个 `[1]` 就算成功吗？

**回答：** 不是。服务端只把本轮通过门禁的证据编号传给模型；流式回答结束后校验引用编号是否存在、事实段落是否带引用，以及引用是否属于本轮候选。第一次格式失败会在完全相同的证据上用温度 0 修复一次，再失败就用 `replace_answer` 撤下不合格文本、清空引用并转人工。

**深入追问：** 引用卡片数据来自 Chunk 元数据和原文，不接受模型伪造的文档名或页码。前端只在相应编号实际出现后展示引用。

## 5. Agent 为什么用单状态机，不做多 Agent？

**回答：** MVP 只有知识回答、订单查询、退货资格和人工接管四种意图。多 Agent 会增加路由波动、延迟、成本和难以解释的状态。显式状态机让每次检索、校验、工具调用、生成和接管都有确定入口、退出条件与审计事件，更适合客服的可信边界。

**深入追问：** DeepSeek 的 Tool Calling 只决定是否选择两个允许工具之一。工具名再次经过 allowlist，参数再经 Zod 校验；业务代码不接受模型给出的 SQL、表名或任意函数。

## 6. 订单工具如何防止越权和隐私泄漏？

**回答：** 匿名顾客必须同时提供订单号和下单邮箱。Repository 先用 Workspace + 订单号执行固定参数化查询，再在服务端比较规范化邮箱；邮箱不匹配时不返回任何订单详情。成功结果只包含状态、关键时间、商品摘要和脱敏姓名/邮箱/运单号。

**深入追问：** `not_found`、`email_mismatch` 和连续数据库异常是三种不同状态。审计日志只保留订单号后四位与邮箱 Hash 前缀，不记录完整凭据。

## 7. 为什么退货资格不能由 LLM 判断？

**回答：** 退货涉及时间窗口、商品类型、密封状态、运输损坏和政策版本，必须可重复。系统先验证订单，再用订单购买时生效的政策版本执行纯函数，输出 `eligible`、`ineligible` 或 `manual_review`、原因码和匹配条款。LLM 只把结构化结果解释成自然语言。

**深入追问：** 三种结果都带 `requiresApproval: true`。即使 eligible，系统也只能生成待人工审批工单，不能退款或修改订单。规则单元测试必须 100% 通过。

## 8. Workspace 隔离只靠 RLS 吗？

**回答：** 不是。浏览器登录后把 Supabase Access Token 交给 Fastify；API 用 `getClaims` 校验 JWT，再查询真实成员关系和权限矩阵。每个 Repository 查询显式携带 Workspace，RLS 是第二道边界。Secret Key 仅在服务端，浏览器只持有 Publishable Key。

**深入追问：** 管理员可管理成员、知识、商品和设置；客服只能读取业务上下文并处理分配工单。未知 Workspace 与未加入 Workspace 统一返回 403，避免通过状态码枚举租户。

## 9. SSE 流式轨迹如何保证不是前端假动画？

**回答：** API 使用 POST + SSE。服务端真实进入理解、检索、校验、工具调用、生成或接管阶段时才发送事件；DeepSeek 的可见 Token 到达后才发送 Token 事件。前端没有用 `setTimeout` 假装推理，只对新事件做 160–240ms 的淡入位移。

**深入追问：** `reasoning_content` 不会传给浏览器。回答完成后轨迹收起但可重新展开；工具只显示结构化摘要，不展示敏感原始 JSON。

## 10. Webhook 如何保证工单创建后不丢事件？

**回答：** 工单创建、状态更新或人工回复与 `webhook_deliveries` 在同一数据库事务中写入，这是事务型 Outbox。后台投递器领取到期记录，使用 HMAC-SHA256、时间戳、超时和有限指数退避投递，并记录响应状态与安全截断的错误。

**深入追问：** Endpoint URL 在保存和每次发送前都解析 DNS，拒绝凭据、环回、私网、保留地址和生产 HTTP，防止 SSRF/DNS Rebinding。独立签名密钥只在创建时显示一次，数据库保存 AES-256-GCM 密文。

## 11. 26/26 的评测结果可靠吗？

**回答：** 它是这个固定 Demo 数据集上的真实基线，不代表所有行业准确率。26 条用例有确定性预期：引用文档、工具、拒答、退货状态和 Workspace 隔离。最新运行真实调用 DeepSeek、SiliconFlow 和 Supabase，结果存进 `eval_runs/eval_results`，落地页读取相同记录，没有写死成绩。

**深入追问：** 初始 Live 只有 21/26。项目保留了 JSON 围栏、工具误路由、弱关键词旁路和引用格式等失败，以及每次修复理由。Mock Provider 只用于 CI 稳定性，不作为公开模型质量结果。

## 12. 指标和成本是怎样记录的？

**回答：** 每次问答记录 Workspace、会话来源、意图、检索候选、最终引用、工具状态、拒答/接管、首 Token 与总延迟、Token、估算成本、反馈和错误类型。供应商不返回的字段保存为 unavailable，不补造。

**深入追问：** Overview 在查询时计算近 30 天运营会话；`evaluation` 来源不占公开 Demo 配额、不创建运营工单，也不污染看板。成本使用环境变量中的供应商费率做保守估算，并明确说明缓存和峰谷差异。

## 13. 文档去重和切块有什么设计细节？

**回答：** 上传先验证扩展名、MIME、PDF 签名、UTF-8、空文件和 10 MB 上限，再计算 SHA-256。相同 Workspace 的同内容直接复用原记录，不新增 Storage 对象或 Chunk。Markdown 按标题层级，PDF 按页，TXT 按段落；Chunk 保留章节、页码、语言、型号和 Hash。

**深入追问：** 默认目标 1,200 字符、重叠 180 字符，但跨章节不继承重叠，防止相似型号或相反政策混在同一证据。扫描 PDF 没有文本时明确失败并提示先 OCR。

## 14. 你遇到的一个真实问题是什么？

**回答：** DeepSeek 规划请求同时启用 JSON Output 和 Tool Calling 时，模型倾向返回文本 JSON 而不发函数调用，订单链路因此失败。我根据实际响应移除模式叠加，按 Tool Calling 协议使用 `tool_choice: auto`；工具名和参数仍由服务端校验。之后订单与退货真实 Smoke Test 通过。

**深入追问：** 这个修复没有降低安全边界。相反，它把“模型怎样表达选择”和“服务端是否允许执行”分开：即使模型输出格式变化，业务工具仍不能绕过 allowlist、Schema、权限和参数化查询。

## 15. 如果上线后质量下降，你会怎样排查？

**回答：** 先按可观察链路定位：是否文档处理失败、Embedding 配置变化、Retrieval@5 下降、阈值拒绝增加、引用校验失败、工具参数错误，还是 Provider 延迟/错误。查看具体候选的向量相似度、关键词排名、RRF 排名、最终引用和错误类型，再用失败问题补充确定性评测。

**深入追问：** 不会先改 Prompt 或降低阈值。先判断是数据、召回、排序、证据门禁、生成格式还是业务工具问题；任何修复都要回跑安全、隔离、退货规则和历史评测，防止“准确率提高但越权”。
