## 改了什么

### 首页：分层的服务流程，而非整板淡入

主线是“问题 → 结果 → 依据 / 下一步”。重新编排首屏演示：深森林底、错开的问题/答案/依据卡、明确的三步侧轴、局部叠层和青绿/暖橙业务语义。保留两行完整标题、主 CTA、原有三种服务示例与历史评测边界。

- 问题从右上进入，结果从左下进入，依据从右下进入；分别从 0 / 300 / 700ms 开始，约 1.3 秒完成。连接线按步骤展开，选中指示连续滑动，不是旧面板统一 180ms 淡入。
- 首次进入视口播放一次，离开视口暂停；在演示内容上悬停可暂停观察。手动切换或“重播流程”再播放，没有自动循环抢走阅读。
- 标题与说明短暂交错入场，CTA 一直可用。按钮有底色、图标位移、阴影及按下反馈。下方区块只首次进入视口短暂出现，返回不再隐藏或重播。
- 示范内容始终标为“已验证流程的示例 · 非实时回答”。切换、重播没有请求模型、创建会话或工单；进入 Demo 仍仅填草稿。
- 无动画框架或新增依赖。动画以 transform / opacity 为主；reduced motion 下内容完整静态可读，选中指示仍正确。

关键文件：`SupportPreview.vue`、`FoundationView.vue`、`styles/support-preview.css`、`styles/landing.css`、`useViewportEntrance.ts`、`useLandingReveal.ts`、`locales/presentation.ts`。

### 来源：统一状态、打开原文、仅定位相关容器

确认旧链路：总入口没有 ordinal → selection 写 null → panel watch 清空展开项；同时 Demo View 无条件把右栏滚回顶部。

- 总入口首次打开该回答的第一条有效来源，已有展开项则保留；正文编号打开准确来源。重复点击不会收起原文，只再定位并显示一次浅色信号。
- 来源的展开项由 `useDemoSelection` 单一管理，右栏手动折叠也更新同一状态，避免两个状态互相覆盖。
- WeakMap 按消息对象保存每条回答的展开项，不能把另一条回答的编号/原文沿用过来。流结束替换服务端消息 ID 不丢失状态；新会话清空记忆。
- 已在可读位置不滚动；屏外时只调整证据容器，并保留原文开头约 96px 的阅读区，不使用会牵动整个页面的 scrollIntoView。目标 summary 使用 preventScroll 聚焦；快速重复动作只定位最后一次选择。
- 手机自动进入资料视图；返回保留草稿、会话和入口焦点。减弱动效仍有静态青绿边框/侧标，原文照常展开。
- 工具-only / 无来源仍显示“查看资料与结果”，不会伪造编号。原有真实工具结果、确认接管与失败状态保持。

关键文件：`useDemoSelection.ts`、`DemoEvidencePanel.vue`、`DemoView.vue`、`styles/demo.css`。未改共享 chat store、安全 Markdown、滚动跟随、反馈或服务端链路。

## 实际操作 → 找问题 → 修正 → 复查

1. 改前读取工作区、第二轮交接与顾问来源证据；记录首页桌面/手机基线。实际提交双设备兼容性问题，确认真实回答及两条产品手册引用。
2. 实现后在浏览器切换场景，观察到问题已进入、结果处于淡入、依据尚未出现的分层时序。随后录制约 10 秒本地 Chromium 视频，检查内部错时出场、滑动指示、重播、CTA hover/press、滚动与减弱动效；查看视频的代表性时间帧，而非用静态终态代替动效检查。
3. 录制初次配置放进 describe 导致 Playwright worker 配置失败；移动到文件顶层后重新运行并录制成功，不把失败运行算通过。
4. 一个来源测试错误地要求“点第二条一定要滚动”。收起第一条长原文后，目标已自然进入视口；正确行为是不滚动。修正断言，并加入实际滚到右栏下方后再定位的屏外检查。
5. 完整双语场景检查发现 390px 英文接管回答与下一步卡间距过紧，阴影接近相碰。增加手机/320px 结果行高度，重新检查 3 场景 × 2 语言 × 4 宽度，卡间保留间隔且切换高度稳定。
6. 将原有预览 CSS 整理进独立样式文件，清除旧手机覆盖。将定位信号放入 summary，维持原生 details 的有效结构。
7. 在真实桌面响应中反复检查总入口、正文第二条、重复入口；手机真实响应验证总入口首开、第二条定位、返回草稿与焦点、再点总入口保留第二条。其他所有权、长原文、异常、工具共存、接管分支使用隔离夹具，不反复调用模型来验动画。
